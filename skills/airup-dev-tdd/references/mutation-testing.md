# Mutation Testing

用变异测试审计测试有效性:对生产代码施加小型语义变化,确认测试能否识别。变异分数是诊断信号,不是独立的质量目标;它不替代行为 RED、边界分析或最终验证。变异结果暴露新产品行为或缺陷时,先转为新的 TDD 切片再改生产代码。

## Preconditions

- 相关测试基线 GREEN,已记录命令、exit code 与通过摘要;基线不稳定或测试 flaky 时先处理,不把基础设施失败计入幸存变异。
- 明确目标生产范围与受保护行为;生成代码、vendor 代码、迁移快照与纯声明文件默认排除,其余排除项须有具体理由,且运行不得覆盖用户未提交的修改。
- 优先使用项目已配置的变异工具与命令;未配置时按语言、runtime 与测试 runner 选择兼容工具。首次运行聚焦变更代码或当前切片,成本可接受时才扩大到模块或全仓库。

## Triage

- Survived:测试执行了变异位置但断言未识别变化,检查缺失的行为断言、边界值、状态转换、错误语义或副作用。
- No coverage:确认是可达行为、死代码、错误范围,还是缺少合适的测试层。
- Timeout:区分可能暴露无限循环或性能风险的变异,与阈值过低、并发竞争或 flaky 测试。
- Error:区分合法的编译杀死、工具不兼容、fixture 问题与环境故障,不得自动计为测试有效。
- Equivalent:仅当可观察行为确实无法区分或不属于目标风险时接受,并记录具体理由。

相同根因可合并分析,但每组保留代表位置与处置依据;不得按文件或操作符批量忽略结果。

## Strengthening Tests

- 为幸存变异补充调用方可观察的结果、错误、状态、顺序、不变量或外部副作用断言,选择能保护该风险的最窄测试层。
- 新测试必须在对应变异存在时失败、在原始代码下通过;重跑聚焦测试确认 GREEN 后,再重跑目标变异确认被杀死。
- 不断言私有方法、具体行号、无业务意义的调用次数或实现细节;不得删除生产行为、放宽变异操作符、扩大排除项或添加无意义断言来提高分数。
- 变异暴露真实缺陷时,先按 TDD 建立回归 RED 再修复,而不是继续刷分数。

## Threshold Policy

门槛按优先级取:项目已声明的阈值或 CI 政策;变更代码分数不低于已记录基线并对高风险新逻辑执行 ratchet;安全、授权、财务、不变量与不可逆副作用等关键逻辑没有未解释的幸存变异。无既有政策时报告实际结果与残余风险,不把任意百分比说成行业标准;分母、排除项或工具版本变化后必须重新说明基线。
